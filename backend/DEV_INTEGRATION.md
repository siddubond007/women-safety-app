# Sakhi Development Backend Integration

This guide is for the local development/test flow only. The development OTP is generated by the backend and shown in the app; no SMS is sent and no mobile carrier verification occurs. The eligibility provider is intentionally unavailable.

## 1. Repair local DB role passwords (only if migration status reports P1000)

From PowerShell, in the backend directory, copy one generated role password to the clipboard without printing it:

```powershell
.\scripts\copy-db-password.ps1 -Role sakhi_dev_migrator
```

In pgAdmin, open Login/Group Roles, right-click sakhi_dev_migrator, choose Properties → Definition, paste into Password and Confirm password, and save. Repeat for sakhi_dev_app, sakhi_test_migrator and sakhi_test_app. Each role must use its own stored password. Do not paste passwords into chat or source files; clear the clipboard when finished.

Check the role login in pgAdmin if authentication still fails. Do not use the postgres superuser as the runtime role and do not reset/drop either database.

## 2. Apply migrations and development seed

Use a normal PowerShell terminal from the backend directory:

```powershell
.\scripts\db-migrate.ps1 -Environment dev
.\scripts\seed.ps1 -Environment dev
```

These wrappers use the dedicated migrator role, apply the tracked migrations and seed only reserved fictional data plus DRAFT policy metadata. They do not run database reset/drop commands. If either command fails, stop and fix the exact reported problem before starting Flutter integration.

## 3. Start the local API

In a separate PowerShell terminal from the backend directory:

```powershell
.\scripts\start-dev.ps1 -Environment dev
```

The wrapper enables the dev-only OTP echo and temporary minimum age 13 for that process. This is not production policy. It binds to 127.0.0.1:3000; OTP echo is rejected on other hosts.

In another terminal, verify readiness:

```powershell
Invoke-WebRequest http://127.0.0.1:3000/api/v1/health/ready -UseBasicParsing
```

Expected response is HTTP 200 with database status ready. A 503 or connection failure means Flutter integration must wait.

## 4. Connect the Android phone over USB

With the phone connected and USB debugging approved, run:

```powershell
D:\applications\And_Studio\platform-tools\adb.exe reverse tcp:3000 tcp:3000
```

This forwards the phone's loopback port 3000 to the development PC's loopback API without exposing OTP echo on the LAN.

## 5. Run Sakhi with the development backend adapter

From the Flutter app directory:

```powershell
D:\Development\flutter\bin\flutter.bat run --dart-define=SAKHI_BACKEND_ENABLED=true --dart-define=SAKHI_API_BASE_URL=http://127.0.0.1:3000/api/v1
```

Only a debug build selects this adapter. Normal debug runs still use the non-persistent demo simulator; release builds use the unconfigured production placeholder.

Flow:

1. Request an OTP. The backend returns the local development code; the app displays it in the labelled LOCAL DEVELOPMENT OTP panel.
2. Enter the displayed code. The backend consumes the OTP challenge, creates the pending development account on registration, and issues a 12-hour development bearer session.
3. Complete profile and acknowledge the current draft Terms/Privacy records. The profile and draft acknowledgement are persisted to sakhi_dev. The optional update preference remains separate.
4. Eligibility screens load the backend configuration/status. The provider remains unavailable, and no verification session or eligibility conclusion is created.

## 6. What this does not do

- It does not send SMS or prove carrier control of the phone number.
- Draft policy acknowledgement is test data, not approved Terms/Privacy acceptance.
- The temporary minimum age 13 applies only to local development/test and must not be reused as production policy.
- No real identity provider, document upload, selfie/liveness, manual review or eligibility decision is implemented.
- No protected production area should be enabled from this development session.

## Troubleshooting

- PostgreSQL P1000: align the corresponding local role password in pgAdmin using the DPAPI helper above; never print or share the password.
- Health readiness 503: inspect PostgreSQL service/readiness and role access; do not run a reset to repair it.
- Phone cannot reach API: confirm backend is running, then re-run adb reverse. Do not change the API host to 0.0.0.0 when using OTP echo.
- Migration fails: preserve the error output and stop; do not run migrate reset, db push, or a manual drop.
